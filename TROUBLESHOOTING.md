# Troubleshooting

This guide covers the most common issues with node selection, Web panel access, and ports.

## First checks

Run these commands from the same account that runs `clashctl`:

```bash
clashctl status
clashctl ui
clashctl node ls
```

If the status says that Mihomo is not running, start it before using the node or controller commands:

```bash
clashctl start
```

If startup fails, inspect the core log:

```bash
clashctl log
```

The active, merged configuration is available with:

```bash
clashctl mixin -r
```

`clashctl mixin -e` opens `<CLASHCTL_HOME>/data/mixin.yaml`, normally:

```text
~/.clashctl/data/mixin.yaml
```

That is the persistent user Mixin file. `resources/mixin.yaml.example` is only the template copied during initialization when `data/mixin.yaml` does not exist; editing the example does not update an existing installation. `data/runtime.yaml` is generated by merging the subscription configuration with `data/mixin.yaml`, so do not edit it directly.

To confirm the path used by the current installation:

```bash
clashctl mixin -h
```

## The IP still shows Moscow

There are two different IP addresses that are easy to confuse:

- `clashctl ui` displays the public IP of the server running clashctl. It uses a direct request to discover that address, so it does not represent the selected proxy node.
- A request sent through the local Clash proxy displays the selected node's exit IP.

Check the strategy groups and their current selections:

```bash
clashctl node ls
clashctl node ls Proxy
```

Switch the `Proxy` group to a specific member. Use the exact name printed by `clashctl node ls Proxy`, including spaces and punctuation:

```bash
clashctl node use Proxy "节点名称"
```

You can also run `clashctl node use` without arguments and choose the group and node interactively. The default Mixin enables `profile.store-selected`, so a manual selection is retained when Mihomo restarts.

Verify the result through the proxy port rather than through `clashctl ui`:

```bash
curl -x http://127.0.0.1:7890 https://ipinfo.io/ip
```

Replace `7890` if `mixed-port` has been changed. If the request still uses the old location, check these points:

1. The selected group is the group used by the matching rule. Selecting `Proxy` does not change traffic that a rule sends to `DIRECT`, `Domestic`, or another group.
2. The node name was copied exactly and the command reported a successful switch.
3. Mihomo is running with the current runtime configuration. Run `clashctl status` and `clashctl mixin -r` again after a restart.
4. The application being tested is using the Clash proxy. A browser or command that bypasses the proxy will show the server or local network IP instead.

## VS Code or a Web panel reports a CORS error

The controller API must allow the origin of the page that is making the request. Configure this in the Mixin file:

```bash
clashctl mixin -e
```

For changing VS Code forwarding URLs, you can temporarily allow all browser origins:

```yaml
external-controller-cors:
  allow-origins:
    - "*"
  allow-private-network: true
```

`"*"` allows requests from any browser origin, which is convenient for changing forwarding URLs but broad. Keep the generated Web secret, avoid exposing the controller directly to the public Internet, and replace the wildcard with an exact origin list when the panel URL is stable. The Mixin example may instead contain a restricted list of exact origins.

For a restricted configuration, replace `"*"` with the page's exact Origin. An Origin contains the scheme, host, and non-default port, but not a path. For example:

```yaml
external-controller-cors:
  allow-origins:
    - https://vscode.dev
    - https://panel.example.com:8443
  allow-private-network: true
```

After saving the Mixin, clashctl validates the merged configuration and restarts the core. Check that the setting reached the runtime configuration:

```bash
clashctl mixin -r
```

The controller also requires the Web secret. Keep the generated secret in the Mixin and provide it to the panel when prompted:

```bash
clashctl secret
```

The controller is configured separately from the proxy listener. CORS changes do not change either port. If the browser still reports CORS, check the browser's request `Origin` value and add that exact value to `allow-origins`, then restart again.

## Opening the panel through VS Code Remote-SSH

When VS Code is connected to the server with Remote-SSH, the controller is listening on the remote machine. Forward that remote controller port to your local computer instead of opening the server's `127.0.0.1` address in a local browser.

On the remote VS Code terminal, start the core and check the controller port:

```bash
clashctl start
clashctl status
```

In VS Code:

1. Open the **Ports** view in the Remote-SSH window.
2. Choose **Forward a Port**.
3. Enter the remote `external-controller` port. The example Mixin uses `9090`; your installation may use another port, so check `clashctl mixin -r` or `clashctl status`.
4. Open the forwarded local address in a browser, for example `http://127.0.0.1:9090/ui`. VS Code may assign a different local port; use the local port shown in the Ports view.

The forwarded panel and controller API use the same local origin, so this route normally avoids the cross-origin problem caused by an external panel. If you use `board.zash.run.place` or another separately hosted panel instead, configure that panel's exact origin under `external-controller-cors.allow-origins` and provide the Web secret.

Test the controller from the remote terminal if the forwarded page does not load:

```bash
controller_port=9090
curl --noproxy '*' -i "http://127.0.0.1:${controller_port}/version"
curl --noproxy '*' -I "http://127.0.0.1:${controller_port}/ui/"
```

Replace `9090` with the effective `external-controller` port. A connection failure means Mihomo is stopped, the port is wrong, or the controller did not bind; inspect `clashctl log`.

## Changing ports

Edit the Mixin file:

```bash
clashctl mixin -e
```

The common settings are:

```yaml
# Applications send HTTP, HTTPS, and SOCKS traffic to this shared listener.
mixed-port: 7891

# The Web panel and controller API listen here.
external-controller: "0.0.0.0:9091"
```

Use these separate settings only when you need separate listeners:

```yaml
port: 7892        # HTTP proxy listener
socks-port: 7893  # SOCKS5 proxy listener
```

If `mixed-port` is set, it is normally the only proxy port applications need. The controller port is the port used by the Web panel, node commands, and controller API; it is not the same as the proxy port.

After editing, save and allow clashctl to validate and restart the core:

```bash
clashctl mixin -e
clashctl status
clashctl ui
```

Use ports that are not already occupied. clashctl can move a conflicting configured port to a random available port during startup, so always use `clashctl status`, `clashctl ui`, or `clashctl mixin -r` to confirm the effective port after a conflict. If the panel is accessed from another machine, also allow the controller port through the server firewall and any VS Code port forwarding.

## The node command cannot connect

`clashctl node` talks to `external-controller`, not to `mixed-port`. Check both values in the runtime config:

```bash
clashctl mixin -r
clashctl status
```

Then confirm that Mihomo is running and that the controller port is reachable locally. A controller bound to `127.0.0.1` is local-only; a controller bound to `0.0.0.0` can be reached through the network, but should be protected with a Web secret and a firewall.

## Configuration changes do not take effect

Use this sequence:

```bash
clashctl mixin -e
clashctl mixin -r
clashctl status
```

The first command writes the persistent Mixin. The second reads the generated runtime configuration. The third confirms whether the core is running and which panel address is active. If validation or restart fails, read the error and inspect `clashctl log` before trying another change.
